## 已知输入特征

| 项目 | 已有证据 | 本工具的处理 |
| --- | --- | --- |
| 传感器 | 四路 OV9281 黑白 global shutter，经 UC-512 聚合 | 首版以 global shutter 灰度图为主 |
| 拼接布局 | 5120 × 800 GREY，四路 1280 × 800 从左到右 | 配置显式 crop，或接收用户已经裁好的图像 |
| 通道身份 | 图像槽位与物理连接器映射尚未确认 | 使用用户定义的 camera ID，不猜连接器编号 |
| 频率 | 该项目部分实测约 44.972 fps，名义设置不一定生效 | 不把 45 fps 写死为真实时间间隔 |
| 曝光控制 | Jetson V4L2 `exposure` 初始值 681，单位未确认 | 保存为原始控制值，不能解释成 681 µs |
| 另一路采集示例 | RPi 脚本请求 4000 µs，并记录 `ExposureTime` | 区分请求值与返回元数据，不把脚本默认值当作本次实测 |
| 单板同步依据 | 120 Hz 手机显示检查中未见差异，约 8.33–10 ms 方法分辨率 | 仍需独立测量四路相机 offset，不能预设为零 |

同一拼接帧仅说明四个视图被封装在同一源帧中，并不构成本工具的精确同步结论。共享曝光控制也不取代逐相机光学估计。

## 接口约束

用户可提供每相机独立 PNG/TIFF 序列；也可提供宽图并在输入配置指定 `[x, y, width, height]`。四路宽图的 x 偏移分别为 0、1280、2560、3840，此配置只适用于已经确认的 5120 × 800 模式。

不自动连接设备或改变曝光。图像以原始灰度/无损保存为优先；如果输入有 JPEG 压缩、饱和或自动曝光变化，解码器记录这些条件及其对有效率的影响。没有曝光元数据时仍可进行定位/光强提取，但定量解码必须在模型可辨识时给出估计，否则输出不确定结果。

若实际曝光为 4 ms，250 µs 槽下会覆盖约 16 个槽（边界部分槽另计），因此需要积分解码，不能假设每帧只亮一颗 LED。这只是根据曝光假设的计算。

厂商传感器说明：[Arducam OV9281 global shutter](https://docs.arducam.com/Raspberry-Pi-Camera/Native-camera/Global-Shutter/1MP-OV9281-OV9282/)。套件具体输入布局以用户实际图像和上述项目记录为准。
